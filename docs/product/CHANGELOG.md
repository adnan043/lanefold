## Boards, lanes, cards

- Board "Share" (2026-11-09), like other kanban tools: board admins (or all non-guest board members, when the board's "Who can add people" allows it) add workspace members with a role (admin, member, viewer), invite anyone by email, or share an invite link; admins change roles and remove people; anyone can leave; workspace members can "Join board" on workspace boards (switchable). People outside the workspace join as GUESTS: a seat on that board only (no workspace membership, never board admin, no chat, search or workspace pages), capped per workspace at the plan's member limit, listed under "Guest boards". Someone removed from the workspace cannot come back as a guest by link or an older invite. Losing a board removes the person from its cards, checklist items, followed cards, notifications and board chat. Email invites reuse the workspace invite pipeline (keyed address hash only, sealed job, 20 languages). Migration `20261109120000_board_sharing` (expand-only). Code: `src/server/routes/board-members.ts`, `src/server/board-seats.ts`, `boardAccess` in `src/server/workspaces.ts`, `src/app/boards/share-board.tsx`. Verified how: unit suite, typecheck, build, integration tests on a throwaway Postgres (`board-members`, `authz-matrix` rows); never opened in a browser.

## Known limitations (still open in code on this date)
- Account deletion now cleans up in the database (see 2026-11-03 entry); orders and memberships keep rows with the buyer email wiped. The in-app preflight screen exists at `/app/settings/account`; nobody has opened it in a browser.
- Masked emails shown to admins: `maskEmail` in `src/server/routes/members.ts` now masks the domain (see 2026-11-04). The platform's own `maskEmail` in `src/platform/auth/admin.ts` (managed code, not editable here) still uses its older mask.
- A board card cursor accepts up to 10 digits and is cast to `int`, so a crafted value above 2^31 probably returns a 500 (`boards.ts`, `review-security-3.md` #3; not run).
- A member removed or demoted may still be able to cancel a workspace plan (`review-security-3.md` #1; not re-verified in `routes/billing.ts`).
- "Create card from message" copies private text into a board with a wider audience (by design, unannounced).
- A card move or card-from-message can land in a lane archived in the same instant (race, LOW).
- A stale card move still bumps the board revision (`review-correctness-server-2.md` #2).
- A late "ended" event from an old subscription can downgrade a workspace with a newer active one (`review-correctness-server-2.md` #1; the `workspace_id` migration helps but is unpublished).
- The 10-card cap on a chat message can be exceeded by a race.
- Board open scans every active card of the board; fine to a few thousand cards (`review-performance.md`). Polling costs about 40 queries per minute per open board with chat.
- Board settings: saving WIP limits after another user adds a lane may clear that lane's limit (`board-settings.tsx`, `review-correctness-client-2.md`; not re-checked on 2026-11-04). The board-name field now keeps an unsent draft (see 2026-11-04).
- Typecheck result not recorded; no browser QA; Noto fonts for ur, th, bn, hi, ar and CJK exist in `public/fonts` but are not browser checked; the UX, accessibility and responsive audit items are unconfirmed.
- Not owner-facing but blocking: sandbox prices must be created, the Storage pack added and migrations published before checkout and uploads work.

Fixed since the reviews (not limitations): private board creator access, chat in read-only workspaces, `/jobs/` indexing, lazy widget failures, member search showing inactive users.

## 2026-11-04 Bulk select: Undo, `x` key, drag in select mode
